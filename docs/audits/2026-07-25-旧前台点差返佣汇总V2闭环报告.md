# 旧前台点差返佣汇总 V2 闭环报告

## 1. 模块范围

- 旧项目：`D:\Php-project\Php\new_co_gmtk_crmV3`
- 新项目：`D:\Software\PhpProject\Demo\co_crmv5`
- 旧入口：`GET /user/position/comm_summaryv2`
- 旧方法：`App\Http\Controllers\User\PositionSummaryController@realTimerealTimeV2`
- 新入口：`legacy_user_position_comm_summary_v2_page`
- 新控制器：`App\Http\Controllers\Front\LegacySpreadCommissionSummaryController@commSummaryV2`
- 新服务：`App\Services\Legacy\LegacySpreadCommissionSummaryService@settleBatch`

本模块不是持仓页面。它是旧系统供定时任务调用的点差返佣入口：读取已平仓订单，逐层计算代理返佣，调用 MT4 入金，并仅在每一笔应付返佣都可证明完成后才结束源交易。

## 2. 路由执行链路

```text
GET /user/position/comm_summaryv2
  -> routes/web.php
  -> LegacySpreadCommissionSummaryController::commSummaryV2
  -> LegacySpreadCommissionSummaryService::settleBatch
  -> settleSpreadTrade
  -> createOrRetrievePayout
  -> processPayout
  -> DepositSettlementGateway::deposit
  -> commission_rebate_payouts + commission_records + user_trades
  -> JSON code=1000 和本批统计
```

1. 路由固定绑定专用控制器，解决旧路径误渲染持仓页面、定时任务没有执行返佣的问题。
2. 控制器只负责调用服务并返回成功 JSON，`data` 包含扫描、成功、可重试、失败、跳过、完成源交易数。
3. 服务只扫描 `cmd=0..5`、已平仓、非零成交量、`margin_rate != 0`、备注不含 `delete`、`settlement_status=0` 的交易，按平仓时间倒序且单批最多 30 条，避免旧任务无界处理。
4. 服务依次校验交易用户、启用的客户组、启用品种、点差类型、代理链、启用代理组和点差配置。任何一项无法证明时都不调用 MT4，也不完成源交易。
5. 对每层代理先持久化出账意图，再调用 MT4；MT4 确认入账后，同一数据库事务写入返佣账本和出账状态。
6. 所有返佣腿的状态均为 `settled` 或 `not_payable` 时才把 `user_trades.settlement_status` 改为 `1`。只要存在 `retryable`、`rejected`、`unknown` 或配置异常，源交易保持待结算。

## 3. 金额规则与结果含义

| 品种点差 | 比例来源 | 计算公式 | 结果 |
| --- | --- | --- | --- |
| `0` | `user_infos.comm_rate` | 比例差 `* volume / 100` | 旧手续费比例返佣 |
| `10`、`20`、`30` | `spread_configs.spread_ratio` | 比例差 `* volume / 100` | 标准点差返佣 |
| `13`、`23`、`33`、`53` | `spread_configs.spread_ratio` | 比例差 `* volume / 100 * 0.1` | 特殊品种点差返佣 |

- `group_configs.has_commission=1` 映射旧客户组 `group_id=1`：直属代理取得本层完整比例。
- `group_configs.has_commission=0` 映射旧客户组 `group_id=0`：直属代理比例先减 `50`；上级代理继续使用与直属下级的比例差。
- 金额使用 BCMath 计算并四舍五入到两位；比例差或金额不大于零时创建 `not_payable` 出账，不调用 MT4。

出账状态的中文含义：

| 状态 | 中文含义 | 是否自动重发 |
| --- | --- | --- |
| `pending` | 已保存待入金意图，尚未发起 MT4 调用 | 可以 |
| `processing` | 当前进程已声明处理权 | 不可以 |
| `settled` | MT4 已确认入金且账本已落库 | 不需要 |
| `retryable` | MT4 明确未发送命令 | 到期后可以 |
| `rejected` | MT4 明确拒绝入金 | 不可以 |
| `unknown` | 命令结果不能证明，或 MT4 成功后本地落账失败 | 绝不自动重发 |
| `not_payable` | 非正金额或线下结算，不需要在线入金 | 不需要 |

## 4. 配置异常保护

- 缺少品种配置：写入 `legacy_spread_commission_missing_symbol:{ticket}` 缓存并隔离 24 小时；源交易仍为待结算。
- 缺少点差配置、代理组、交易用户组、代理链或检测到代理环：按原因写入独立缓存和批量隔离索引，24 小时内不重复尝试。
- 未支持的点差：不回退到点差 `0` 公式，避免以错误金额真实入金。
- 所有上述情况均增加 `failed_count`，中文含义是“本次未能安全完成，需要修复配置或人工核对”，不是“返佣已完成”。

## 5. 审计与数据迁移

`commission_rebate_payouts` 新增以下快照字段：

- `calculation_type`：固定为 `legacy_spread_comm_summary`，区分手续费返佣和点差返佣。
- `spread`：保存本次使用的品种点差。
- `volume_multiplier`：标准品种为 `1.0000`，特殊品种为 `0.1000`。

`commission_records.data_type` 扩容至 50 字符。原因是完整审计标识 `legacy_spread_comm_summary` 长 26 字符，旧字段的 20 字符限制会导致“MT4 已成功、本地账本失败”的 `unknown` 状态。迁移保留字段内容，不执行危险的反向截断。
