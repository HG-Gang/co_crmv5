```text
  -> JSON code=1000
  -> module-page.js 渲染金额、手数、合计和可点击的代理编号
```


按账号搜索链路如下：

```text

  -> 返回一行代理汇总；不会调用 positionDetail，也不会返回 ticket
```

## 4. 旧 MT4 统计口径

所有统计均基于 `user_trades.close_time` 的日期范围，默认时间为 `2024-01-01` 至当天。`symbol` 筛选在读取交易时同步生效。

| 字段 | 计算规则 | 返回中文含义 |
| --- | --- | --- |
| `total_yuerj` | `cmd=6`、金额大于零、备注命中入金白名单 | 代理网络内的 MT4 余额入金 |
| `total_yuecj` | `cmd=6`、金额小于零、备注命中出金白名单 | MT4 余额出金，保持负数 |
| `total_rebate` | `cmd=6`、备注命中 `DBCN` | MT4 返点余额变动 |
| `total_net_worth` | 入金减出金绝对值再加返点 | 旧页面定义的净入金 |
| `total_profit` | `cmd=0..5`、已平仓、`margin_rate != 0` 的 `profit` 总和 | 有效已平仓盈亏 |
| `total_comm` | 有效已平仓 `commission` 总和的绝对值 | 手续费，统一正数展示 |
| `total_swaps` | 有效已平仓且为负的 `swaps` 总和 | 库存费，负数表示成本 |
| `total_noble_metal` 至 `total_stock` | 启用 `symbol_prices` 品种组 `1..6` 的有效成交量除以 100 | 贵金属、能源、外汇、指数、货币和股票手数 |
| `total_volume` | 所有有效已平仓 `volume` 除以 100 | 总手数 |

入金白名单为 `DBAA`、`DBCT`、`DBGN`、`DBMN`、`DBPA`、`DBPN`、`DBSN`、`DBTN`、`DBUN`、`DBZN`、`DBAD`、`WBIR`；出金白名单为 `WBAA`、`WBCN`、`WBCT`、`WBHN`、`WBIN`、`WBPN`、`WBSN`、`WBTN`、`WBAD`、`DBZR`。普通描述文本不会被当作入出金，避免扩大旧系统统计范围。

## 5. 权限、错误与返回结果

1. 登录态不存在时，旧 session 和前台 guard 都无法解析用户，返回 `code=4001`，中文含义为“认证失败”。
2. 登录用户不是代理时，三个代理汇总入口返回 `code=4006`，中文含义为“权限不足”。普通客户不能借由 `userId`、`userPId` 或现代接口读取代理网络。
3. `subAgentsListSearchV2` 传入不在当前代理树内的 `userPId` 时返回 `code=4006`，不返回外部代理资料。
4. `clickSearch` 的目标不存在或不是代理时返回 `code=4005`，中文含义为“参数校验失败”。这阻止把客户账号当作代理汇总根节点。
5. 找不到姓名匹配代理或目标代理没有直属代理时仍返回 `code=1000`、空 `data.list.data` 和零值 `data.totalRow`，中文含义为“查询成功但没有符合条件的数据”。
6. 正常查询返回 `code=1000`：`data.list` 是可分页表格行，`data.totalRow` 是全部匹配行合计，`data.summary` 与合计同口径，`data.chain` 是当前代理下钻路径。

## 6. 本次修复原因与结果

旧迁移代码存在四个关键偏差：主查询只统计代理本人、资金字段错误读取申请表和账户净值、下钻忽略 `userPId`、点击搜索错误委托给交易明细接口。本次改为一次批量读取授权范围内的 `user_trades`，再按各代理完整后代范围聚合。

这样做解决了以下问题：

- 根代理首次查询不再漏算下级代理与客户的 MT4 入金、出金、返点、盈亏和手数。
- `DBCN` 不再错误从 `commission_records` 取数，而是按照旧项目的 MT4 余额备注计算。
- 下钻行不再只统计直属客户，能够统计该直属代理的完整后代网络。
- 账号搜索不再泄露 `ticket`、订单时间等交易明细字段，持仓汇总与交易明细职责重新隔离。
- 现代页面的 `userId`、`userName` 和直属代理入口均有实际、受权且可重复验证的后端行为。
