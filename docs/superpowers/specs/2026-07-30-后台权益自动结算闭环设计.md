# 后台权益自动结算闭环设计

## 目标

把旧项目 `RightsSummaryController::ConfirmWithdrawOrdeposit` 的资金结算能力迁移到新项目，并修正旧实现把业务用户 ID 直接当作 MT4 登录号、远端结果字段不一致、并发重复提交和本地状态无法恢复的问题。

## 业务边界

- 现代接口以 `rights_settlements.id` 为唯一资源主键，不能使用 `user_id` 猜测记录。
- 业务用户通过 `rights_settlements.user_id -> user_infos.user_id -> user_infos.mt4_code` 解析真实 MT4 登录号。
- `rights_settlements.amount` 是应结算金额；请求中的 `real_amount` 必须与明细合计一致。
- `other_amount` 为空时，实际执行金额等于 `real_amount`；填写时，执行金额等于 `real_amount - abs(other_amount)`。
- 执行金额大于零时调用入金网关，小于零时调用出金网关，等于零时拒绝自动 MT4 操作并保留人工确认入口。
- MT4 未明确返回成功及有效订单号时，不得把本地 `status` 推进为已处理。

## 数据设计

`rights_settlements` 转换为 InnoDB，并增加以下字段：

| 字段 | 用途 |
| --- | --- |
| `settlement_type` | `deposit` 或 `withdraw`，保存本次实际资金方向。 |
| `settlement_date` | 保存旧项目 `sumdata` 对应的结算周期文本。 |
| `mt4_login` | 保存执行时解析出的 `user_infos.mt4_code` 快照。 |
| `mt4_comment` | MT4 CMD=6 唯一对账备注。 |
| `mt4_order_id` | MT4 明确成功或对账命中的订单号。 |
| `processing_state` | `pending`、`processing`、`retryable`、`unknown`、`rejected`、`settled`、`manual_confirmed`。 |
| `error_code` | 网关失败或校验失败后的稳定错误码。 |
| `attempt_count` | 已认领并发起处理的次数。 |
| `processing_started_at` | 当前处理认领时间，用于识别崩溃后的陈旧认领。 |
| `processed_at` | 自动或人工确认完成时间。 |
| `processed_by` | 执行确认的后台管理员 ID。 |

`rights_settlement_temps` 同时转换为 InnoDB，并增加 `settlement_id`，使每条明细明确归属单个权益结算记录。自动确认必须按 `settlement_id` 汇总明细，不能跨周期按用户 ID 混算。

## 执行链

1. 路由严格校验 `rights_settlements.id`、`real_amount`、`other_amount` 和 `settlement_date`。
2. 查询结算记录并校验后台管理员数据范围。
3. 加锁读取结算记录、业务用户和明细合计；记录已处理时直接拒绝重复调用。
4. 校验请求周期、实返金额、扣款后执行金额和明细合计。
5. 生成稳定 MT4 备注，并检查 `mt4_trades.login + cmd=6 + abs(profit) + comment` 是否已有记录。
6. 已存在 MT4 记录时，用其 `ticket` 对账完成本地状态，不再次调用网关。
7. 不存在时用条件更新把记录从可处理状态原子认领为 `processing`，并提交本地认领事务。
8. 根据资金方向调用现有入金或出金网关。
9. 明确成功时写入订单号、已处理状态和操作日志。
10. `retryable_not_sent` 回到可重试状态；`unknown` 和 `rejected` 保持未处理并失败关闭，必须由管理员核对或人工确认。

## 并发与故障

- 原子条件更新保证同一结算记录只有一个请求获得处理权。
- `processing` 超过五分钟可按陈旧认领恢复，但恢复前仍会先执行 MT4 明细对账。
- 远端成功后本地写入失败时，下次调用通过 CMD=6 对账收敛，不重复发起资金动作。
- `unknown` 表示请求可能已送达，不能自动重试；`retryable` 表示确认未发送，可再次提交。
- 所有状态变化写入 `operation_logs`，包含管理员、结算记录、业务用户、MT4 登录号、金额、方向、前后状态和错误码。

## 测试矩阵

- 请求参数、路由 ID、数据范围、缺少业务用户、缺少 MT4 登录号。
- 明细缺失、明细金额不匹配、扣款后方向变化、零金额。
- 入金成功、出金成功、连接未发送、未知结果、明确拒绝。
- 已处理重复调用、并发认领失败、陈旧处理恢复。
- 已存在 MT4 CMD=6 记录时本地对账完成且网关零调用。
- 人工确认同步写入 `manual_confirmed`、处理人、处理时间和操作日志。
- 现代路由、旧 `confirm_options` 兼容响应、权限、Blade 按钮、Lucide 图标和中文文案。
