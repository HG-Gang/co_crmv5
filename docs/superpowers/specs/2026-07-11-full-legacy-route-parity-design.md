# 新旧项目全量逐路由逻辑闭环设计

**目标：** 以旧项目 `D:\Php-project\Php\new_co_gmtk_crmV3` 的真实路由、Controller 方法和 Blade/JavaScript 调用为基准，补齐新项目普通用户、代理商、后台管理员三端全部前后端逻辑、权限边界和闭环测试，并生成每条路由详细执行链路的全量 Markdown 报告。

**实施口径：** 保留旧项目正确业务语义和兼容入口，不复制旧项目中明显的越权、宽松参数校验、错误状态流转、静默失败或伪成功行为。新项目现有安全边界、Laravel 8 约束、数据权限和测试证据优先于旧项目缺陷。

**最终计量：** 完成后报告持续目标的总 token 使用量；总耗时统一使用秒作为单位。

---

## 1. 权威输入

范围判断按以下优先级取证：

1. 旧项目 `app/Http/routes.php` 中实际注册的路由。
2. 旧项目路由对应的 Controller 方法、服务调用、模型查询和响应结构。
3. 旧项目 `resources/views/user`、`resources/views/admin` 及关联 JavaScript 的请求字段、页面动作和响应消费方式。
4. 新项目 `routes/front.php`、`routes/admin.php`、`routes/web.php`、`routes/api.php` 的当前注册状态。
5. 新项目 Controller、Service、Support、Model、Middleware、Blade/JavaScript 和数据库迁移的真实实现。
6. 新项目现有测试与 `docs/admin-backend-blade-permission-final-checklist.md` 中可复现的测试证据。

早期“100%完成”报告仅作为历史参考；如果与当前代码、当前路由或可执行测试冲突，以当前可验证证据为准。

## 2. 总体执行顺序

工作拆成四个连续子目标，每个子目标完成实现、针对性测试和模块回归后才进入下一个：

1. 普通用户模块。
2. 代理商与大代理模块。
3. 后台管理员模块。
4. 全量路由审计、全量回归、页面冒烟和最终报告。

每个子目标内部按“旧路由入口 → 新路由映射 → 页面调用 → 权限与归属 → 业务数据流 → 错误路径 → 测试证据”的顺序处理。

## 3. 逐路由映射模型

每个旧项目路由都建立一条审计记录，至少包含：

- 旧项目 HTTP 方法、URI、路由名、Controller 方法。
- 旧项目页面或 JavaScript 调用位置。
- 新项目对应 HTTP 方法、URI、路由名、Controller 方法。
- 兼容策略：直接保留、别名映射、合并到新接口、明确废弃。
- 认证中间件、角色要求、按钮权限和数据范围。
- 请求参数、字段别名、类型、枚举、默认值和归属来源。
- Controller 到 Service/Support/Model/数据库或 MT4/支付通道的执行链。
- 正常响应、验证失败、无权限、数据不存在、状态冲突和外部依赖失败响应。
- 前端页面如何消费响应、刷新状态、展示错误或下载文件。
- 对应测试文件、测试命令和当前结果。

旧路由只有在新项目存在明确映射和可执行证据时才标记完成。仅有同名 Controller 或静态页面不算闭环。

## 4. 普通用户模块设计

覆盖注册、登录、退出、找回密码、验证码、首页消息、个人资料、头像、实名认证、银行卡、联系方式、账户、凭证、入金、出金、资金流水、订单、持仓、新闻、礼品、销户、关系链和旧入口兼容。

核心边界：

- 当前登录用户身份只能来自认证上下文，不能由请求中的 `user_id`、`uid`、`puid` 或别名覆盖。
- 详情、修改、上传、下载、资金申请和销户必须验证资源归属。
- 金额、状态、分页、路由 ID 和枚举字段在查询或整数转换前严格校验。
- 入金、出金、凭证、银行卡和销户写入使用明确状态机；重复提交不得产生重复流水或重复扣款。
- 支付、MT4、邮件、短信和文件处理失败必须返回真实失败，不写入伪成功状态。
- 普通用户不能访问代理商专属列表、统计、客户管理、返佣和层级操作。

前端必须覆盖旧页面的真实表单字段、筛选、详情动作、上传、下载、错误展示和提交后的状态刷新。

## 5. 代理商与大代理模块设计

覆盖下级代理、直属客户、代理树、关系路径、代理统计、客户详情、客户登录历史、等级确认、客户转组、实时返佣、历史返佣、返佣转账、资金流水、持仓、订单和大代理独立登录入口。

核心边界：

- 代理身份来自当前登录上下文；请求参数只能指定目标资源，不能替换申请人身份。
- 统一使用 `FrontLegacyData::userScopeIds` 或经验证的同一共享入口解析 `user_infos.parent_id` 与闭包表兼容关系，避免多套代理树口径。
- 所有目标代理、客户、订单、持仓、流水和返佣必须落在当前代理可见范围内。
- 普通客户无法访问代理专属读写接口；代理也不能越级操作范围外用户。
- 返佣计算、转账、等级变更和客户转组使用事务、余额校验、状态校验和操作记录。
- 下载文件和导出结果必须绑定当前申请人与可见范围，不能通过已知文件名绕过授权。

前端需保持代理列表钻取、客户详情弹层、路径展示、筛选、导出、转账和确认动作的完整交互。

## 6. 后台管理员模块设计

覆盖后台登录、当前管理员资料、管理员账号、角色、权限、菜单、数据范围、用户、代理、代理等级、大代理、实名认证、入金、出金、返佣、资金流水、交易、持仓、权益、风控、仓位清零、在线用户、凭证、注销、新闻、礼品、支付渠道、产品、组别、系统配置和批量导入。

核心边界：

- 每个后台路由同时验证登录态、按钮权限和数据范围，不以页面是否隐藏代替后端授权。
- 路由参数与请求体 ID 在数据库查询前严格校验；筛选枚举和数值字段使用白名单。
- 用户、代理、资金和交易查询必须应用管理员数据范围，导出与列表保持同一过滤口径。
- 审核、启停、结算、强平、清零、导入重试等写操作必须验证当前状态与允许的状态迁移。
- 管理员修改自身资料与修改其他管理员账号使用不同归属规则，密码字段不得在读取接口泄露。
- 配置、菜单、权限、角色和数据范围变更必须避免部分写入，并保留必要审计记录。

后台 Layui、AdminLTE、CRMUI 和 Naive UI 入口需要映射到真实后端能力，按钮显示、请求字段和错误反馈保持一致。

## 7. 错误处理和数据一致性

- 参数错误统一在数据库查询、数字强转或外部调用前返回验证失败。
- 未登录、无按钮权限、超出数据范围和资源不归属使用可区分的失败响应。
- 资源不存在与参数格式错误不能混为同一结果。
- 状态冲突直接失败，不通过隐式默认值绕过状态机。
- 多表写入、余额变化、返佣转账、审核和批量处理使用数据库事务。
- 外部服务异常保留真实错误上下文并回滚本地未完成写入。
- 不吞异常、不返回假成功、不用空集合掩盖本应暴露的连接或业务错误。

## 8. 测试与验证策略

每个发现的缺口采用 TDD：

1. 新增最小失败测试，证明当前缺口真实存在。
2. 运行目标测试确认 RED。
3. 实施最小根因修复。
4. 重跑目标测试确认 GREEN。
5. 运行同 Controller、同模块和权限边界回归。
6. 更新闭环清单，记录变更文件、RED/GREEN 命令、证据和未改动边界。

全部模块完成后执行：

- PHPUnit 针对性测试。
- 普通用户、代理商、后台管理员分组回归。
- 全量 PHPUnit 测试。
- `php artisan route:list` 路由注册检查。
- Blade 路由名、JavaScript API 地址、静态资源和权限菜单一致性检查。
- 关键登录、列表、详情、写入、导出和下载页面的最小浏览器冒烟测试。
- 数据库迁移状态、真实数据库连接和关键表结构检查。

如果某项验证因外部依赖不可用而不能运行，不能标记全量完成，必须恢复依赖或保留目标为未完成状态。

## 9. 最终交付报告

最终生成一份全量 Markdown 报告，至少包括：

- 新旧项目范围、版本、路由总数和模块总数。
- 普通用户、代理商、后台管理员模块完成矩阵。
- 每个路由方法的详细执行链路。
- 旧路由到新路由的映射与兼容方式。
- 每个相关变更文件的逻辑说明和交叉影响。
- 权限、数据范围、资源归属、状态机、事务和外部服务边界。
- 测试命令、测试数量、通过结果和浏览器冒烟结果。
- 未实现、无法验证或存在风险的项目；只有此列表为空才允许声明完成。
- 持续目标总耗时，单位为秒。
- 持续目标总 token 使用量。

## 10. 完成判定

同时满足以下条件才可结束持续目标：

1. 旧项目所有有效路由均有明确的新项目映射或有证据支持的废弃结论。
2. 三端前端页面与后端接口之间不存在未接线动作。
3. 所有读写入口闭合认证、权限、数据范围、资源归属、参数和状态边界。
4. 针对性测试、模块回归、全量测试和关键页面冒烟均通过。
5. 全量路由执行链路报告生成并完成一致性复核。
6. 最终报告中的未完成与未验证清单为空。
7. 总耗时以秒、总 token 使用量以目标统计结果给出。
