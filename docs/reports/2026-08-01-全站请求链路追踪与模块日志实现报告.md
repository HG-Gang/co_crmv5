# 2026-08-01 全站请求链路追踪（request_id / trace_id）与模块日志实现报告

> 生成时间：2026-08-01
> 范围：新项目 `co_crmv5` 全部 web/api 接口

## 一、需求与结论

1. 前后端每一个接口的返回都带上 `request_id`（ULID 生成）与 `trace_id`（UUID 生成）。
2. 每一个接口记录相关日志（请求参数 + 响应），按模块 daily 通道落盘。
3. 模块清单按确认结果：**22 个模块**（前台 9 + 后台 13，排除 front_gift / admin_news）。

结论：全部实现并经单元测试（4）+ 功能测试（7）+ 真实 HTTP 冒烟验证。

## 二、实现清单

### 1. `app/Support/RequestTrace.php`（标识生成器）

- `RequestTrace::ulid()`：标准 ULID（Crockford Base32，26 字符 = 48 位毫秒时间戳 + 80 位随机），
  实现与用户提供的官方规范参考逐行一致（时间部分 10 字符高位到低位；随机部分每累积 5 bit 输出一字符；余位左移补齐）。
- `RequestTrace::uuid()`：UUID v4（复用 `Str::uuid()`，依赖 ramsey/uuid）。
- 零第三方新依赖（不依赖 symfony/uid）。

### 2. `app/Http/Middleware/RequestTraceMiddleware.php`（全局中间件，web + api 组）

- **入口（handle）**：
  - 生成 `request_id`（ULID）+ `trace_id`（UUID）；
  - `Log::withContext` 全局关联两个标识（本请求内所有日志自动携带）；
  - 按 `config/trace.php` 前缀映射判定模块，命中且开关开启时记录
    `{模块名}=请求参数` 日志（含 data/url/method/ip/headers/request_id/trace_id，敏感字段脱敏）；
  - 响应注入：`X-Request-Id` / `X-Trace-Id` 响应头 + JSON 响应体同名字段。
- **出口（terminate）**：记录 `{模块名}=响应日志`（status + body 摘要 + 两个标识）。
  - JSON 响应记录正文（2048 字节截断）；
  - HTML 文本响应记录 300 字符摘要 + 总长度；
  - 二进制/图片/文件响应只记录 `[binary 类型, 字节数]`，不落正文。
- **脱敏**：请求参数中 password/passwd/pwd/secret/token/code/sign 类字段掩码为 `******`；
  Header 中 authorization/cookie/x-csrf-token/x-xsrf-token 掩码。

### 3. `app/Exceptions/Handler.php`（异常响应兜底注入）

- 路由级异常（404/405，发生于中间件管道之前）由 Handler 兜底生成并注入 request_id/trace_id，
  保证"每一个接口的返回都带上标识"对异常响应同样成立。

### 4. `config/trace.php`（模块映射）

- 22 个模块的 URL 前缀清单（前匹配优先）+ 脱敏 Header 清单 + 响应正文上限。

### 5. `config/logging.php`（模块日志通道）

- 22 个 daily 通道，均按约定格式：
  ```php
  '模块名' => [
      'driver' => 'daily',
      'path'   => storage_path('logs/模块名/模块名.log'),
      'level'  => 'debug',
      'days'   => 7,
  ],
  ```
- daily 驱动实际落盘文件：`storage/logs/{模块名}/{模块名}-YYYY-MM-DD.log`。

## 四、说明与边界

- 中间件注册于 web 与 api 组最前；静态资源（public/）不经 Laravel 不产生日志。
- 请求日志在 handle 入口记录；响应日志在 terminate 记录（真实 HTTP 场景生效）。
- 日志开关：`TRACE_LOG_REQUESTS=false` 可整体关闭接口日志（链路标识仍注入）。
- 未命中模块的请求（如 /whstest、静态探针）仅注入标识，不写模块日志。
