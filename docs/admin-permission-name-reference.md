# 后台权限名称、字符串与功能作用说明

> 数据来源：当前真实数据库 `permissions` 表，筛选条件 `guard_type=admin`。本文档用于给后台角色授权、菜单显示、按钮显隐和接口鉴权提供中文说明。

## 字段说明

- `权限名称`：来自 `permissions.name`，是后台权限管理页面展示给管理员看的名称；如果历史数据存在编码乱码，本文档会在不改数据库的前提下做可读中文还原。
- `权限字符串`：来自 `permissions.slug`，是角色授权、Blade/JS `data-permission` 和按钮显隐判断使用的稳定字符串。
- `接口路由字符串`：来自 `permissions.api_route`，对应 Laravel 命名路由；`check.permission:admin` 会用它做接口层鉴权。
- `页面路由`：来自 `permissions.route`，通常是后台 Blade 页面地址或菜单跳转地址。
- `类型`：`1=菜单权限`、`2=页面权限`、`3=按钮/接口权限`。
- `功能作用`：根据权限类型、名称、页面路由和接口路由生成的中文说明，用来解释该权限控制的业务边界。

## 权限名称中文注释规则

- 每一条后台权限必须在“权限明细”表格中占用独立一行，不能只在其他段落零散出现。
- `权限名称` 必须使用可读中文，说明当前权限控制的菜单、按钮、页面或接口动作。
- `权限字符串` 必须逐字写出 `permissions.slug`，用于角色授权、Blade/JS `data-permission` 和按钮显隐判断。
- `接口路由字符串` 必须逐字写出 `permissions.api_route`；没有独立接口路由时写 `-`，表示仅控制页面入口、菜单容器或前端动作。
- `页面路由` 必须逐字写出 `permissions.route`；没有 Blade 页面路由时写 `-`，表示仅控制按钮或接口动作。
- `功能作用` 必须点名当前权限名称，并说明该权限在菜单显示、按钮显隐、页面入口或接口鉴权中的控制边界。

## 维护规则

- 新增后台菜单、页面、按钮或接口权限时，必须先写入 `permissions` 表，再同步补充本文档。
- `permissions.slug` 必须保持稳定，禁止因为显示文案调整而随意改动，否则会影响角色授权和前端按钮显隐。
- `permissions.api_route` 必须与 `routes/admin.php` 中的后台 API 命名路由一致，否则 `check.permission:admin` 无法正确完成接口鉴权。
- 超级管理员仍需通过 JWT 与 SSO 确认身份；普通后台角色必须通过 `role_permissions` 授权后才能看到对应菜单、按钮或访问接口。
