# 2026-07-25 旧前台客户登录历史协议闭环报告

> 本文仅记录 `POST /user/cust/loginHistorySearch/{uid}` 的旧前台兼容闭环，不代表旧项目全部模块已经迁移完成。全量进度仍以 `docs/audits/旧项目模块逻辑迁移核验矩阵.md` 为准。

## 1. 本轮目标

旧项目客户详情 Blade 通过 `page + rows` 请求登录历史，并直接读取 `login_id`、`login_id_desc`、`login_ip`、`login_date` 字段。新项目已经有对应路由和数据表，但存在三个会造成旧页面行为偏差的风险：

1. 通用分页器没有识别旧 WidgetPage 的 `rows` 参数，第二页可能错误为空。
2. 新表 `user_login_logs.login_id` 是认证账号主键，不能直接作为旧表格中的业务用户号展示。
3. 旧 `login_id_desc` 字段承载 IP 地理位置，新表改名为 `ip_location`，若不回填会出现空列。

本轮将以上问题固定为可重复执行的真实 HTTP 回归测试，并在新项目完成兼容映射。

## 2. 项目 1：旧项目执行链路

旧项目目录：`D:\Php-project\Php\new_co_gmtk_crmV3`

### 2.1 路由与 Blade 调用

1. 路由 `POST user/cust/loginHistorySearch/{uid}` 指向 `User\DirectCustomerController@loginHistorySearch`。
2. `resources/views/user/user_detail/show_direct_cust_info.blade.php` 在客户详情页初始化 `$.WidgetPage`。
3. 该组件把请求地址设置为 `/user/cust/loginHistorySearch/{uid}`，携带 CSRF Token、`page` 与 `rows`，并将根级 `rows/total` 渲染到旧表格。
4. 旧 Blade 列字段含义如下：

| 旧字段 | 中文含义 | 数据来源 |
| --- | --- | --- |
| `login_id` | 客户业务用户号 | `system_login_log.login_id` |
| `login_id_desc` | IP 归属地说明 | `system_login_log.login_id_desc` |
| `login_ip` | 登录 IP | `system_login_log.login_ip` |
| `login_date` | 登录时间 | `system_login_log.login_date` |

### 2.2 控制器与数据库链路

`DirectCustomerController::loginHistorySearch($uid)` 的旧逻辑按以下顺序执行：

1. 将目标客户号写入 `user_id`，默认时间范围设为“当前日期向前四周的零点”到“当前日期的 23:59:59”。
2. 调用 `get_user_login_history_list('page', $data)` 读取分页记录；有记录时再调用 `count` 获取总数。
3. `SystemLoginLog` 查询 `system_login_log`，过滤 `login_id = {uid}` 与 `voided = '1'`。
4. 使用 `login_date` 做闭区间过滤，按 `login_date DESC` 排序。
5. 基础控制器根据 `page` 和 `rows` 计算 offset，返回根级 JSON：`rows` 是当前页数组，`total` 是符合条件的总记录数。

这条链路解决的问题是让代理在客户详情中查看最近四周的有效登录审计记录；`voided != '1'` 的失效记录不应显示。

## 3. 项目 2：新项目实现与映射

新项目目录：`D:\Software\PhpProject\Demo\co_crmv5`

### 3.1 路由与安全边界

路由 `POST /user/cust/loginHistorySearch/{uid}` 位于 `routes/web.php`，指向 `Front\AgentController::legacyLoginHistorySearch`，并经过 `web` 中间件链。

执行时的安全边界如下：

1. `web` 先校验 Cookie、Session 和 CSRF。没有请求令牌时返回 HTTP 419，表示请求不是可被信任的旧页面表单提交。
2. `legacyFrontUserLogin()` 解析当前前台登录身份。未登录或账号类型不是代理商（`account_type != 1`）时，兼容接口返回 `{"rows":[],"total":0}`，不会泄露任何登录历史。
3. `canViewUser()` 通过 `FrontLegacyData::userScopeIds()` 验证目标用户在当前代理可见的树内；跨树访问同样返回空列表和零总数。
4. `UserLoginLog` 继承 `BaseModel` 的软删除范围，`deleted_at` 非空的记录自动被排除。这对应旧表的有效记录条件 `voided = '1'`。

### 3.2 数据查询与分页链路

`AgentController::legacyLoginHistorySearch()` 的执行步骤为：

1. 以 `user_login_logs.user_id = {uid}` 查询目标用户登录日志。这里使用业务用户号，而不是认证账号主键。
2. 计算最近四周的起止 Unix 时间戳，过滤 `created_at` 在闭区间内的记录。
3. 先克隆查询计算 `total`，再按 `created_at DESC` 查询当前页。
4. 调用 `FrontLegacyData::perPage()` 解析分页大小。参数优先级为 `per_page`、`limit`、`rows`；其中 `rows` 使旧 WidgetPage 的 `page + rows` 请求继续可用。结果被限制在 1 至 100，避免非法页大小扩大查询范围。
5. 将新表字段转换为旧表格字段后，在根级返回 `rows/total`。

### 3.3 字段映射与返回结果

| 新表字段 | 返回字段 | 中文含义 | 为什么这样处理 |
| --- | --- | --- | --- |
| `user_login_logs.user_id` | `login_id` | 客户业务用户号 | 新表的 `login_id` 是 `user_logins.id`，若直接返回会把认证主键误显示为客户号。 |
| `user_login_logs.ip_location` | `login_id_desc` | IP 归属说明 | 旧 Blade 固定读取该名称；保留 `ip_location` 作为新接口扩展字段。 |
| `user_login_logs.login_ip` | `login_ip` | 登录 IP | 与旧字段含义一致，直接返回。 |
| `user_login_logs.created_at` | `login_date` | 登录发生时间 | 新库保存 Unix 时间戳，使用 `FrontLegacyData::dateTime()` 格式化为 `Y-m-d H:i:s`。 |
| 查询总数 | `total` | 最近四周内的有效记录总数 | 用于旧表格分页器计算总页数。 |

返回结果的中文解释：

- `rows` 有数据且 `total > 0`：当前代理有权读取目标用户，返回的是当前页的最近四周有效登录记录。
- `rows=[]` 且 `total=0`：没有符合时间范围的记录，或者当前会话不具备代理身份/目标用户不在可见范围；兼容接口不会通过响应区分这两种情况，避免越权探测。
- HTTP 419：缺少或无效 CSRF Token，调用方必须从旧页面携带 Token 后重新提交。
