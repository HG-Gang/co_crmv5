## 1. 目标

本轮工作需要同时达到以下目标：

1. 全量检查新项目每个业务模块是否实现旧项目对应行为。
2. 对缺失、错误或未闭环的逻辑进行修复，使新项目具备替换旧项目的条件。
3. 允许修正旧项目本身的缺陷，但必须记录旧行为、新行为和修正理由。
4. 全量优化所有 Blade 页面，统一采用视觉方向 C“强对比数据台”。
5. 保持 Laravel Blade 前后端不分离架构，页面布局与交互由 CSS 和 JavaScript 实现。
6. 在隔离数据库完成 schema 重放、数据迁移演练和全量测试，不操作正式目标库。

“100%替换”是工程验收定义，不是有限测试能够给出的数学证明。达到该结论必须同时满足：没有未映射入口、未解释差异、已知失败、跳过测试、假成功分支或未验收页面。

## 2. 已确认决策

- 逻辑验收采用业务结果等价，而非逐行照抄旧代码。
- 旧项目缺陷可以修正，所有合理差异必须进入差异清单并有测试证据。
- Layui 与 CrmUI 两套页面族全部保留并全部优化。
- 视觉方向采用 C：黑灰基底、警示黄重点色、紧凑表格、强状态对比。
- 旧库 `hank_zl_data` 永久只读。
- 数据迁移与全量测试只在隔离库执行。
- 未经用户再次明确确认，不得删除、清空、重建或迁移正式 `co_crmv5`。
- MT4 及用户同步在迁移和测试期间保持禁用，不建立真实外部连接。

对于本轮目标，本文在冲突处优先于 2026-08-05 全项目验收设计和 2026-07-31 双 UI 设计。旧文档继续作为历史证据，但其中涉及正式库直接重建、其他视觉方向或未在本轮确认的约束不自动继承。Layui 与 CrmUI 是页面族名称，两者都采用视觉方向 C，不代表两种不同视觉方向。

## 5. 方案比较与选型

### 5.1 执行路径 E1：逐模块纵向闭环（采用）

每个模块依次完成旧行为盘点、差分测试、后端修复、双 UI 优化、模块回归和证据归档。该方案能够限制变更范围，使每个模块独立验收和失败阻断。

### 5.2 执行路径 E2：后端全部完成后统一处理 UI（不采用）

短期内后端盘点速度较快，但前后端字段、状态和失败语义问题会延迟暴露，并造成后期集中返工。

### 5.3 执行路径 E3：全项目一次性改造后统一回归（不采用）

表面批次最少，但无法可靠定位跨模块回归，也难以证明约 800 条路由和全部 Blade 没有遗漏。

## 6. 总体架构

每个模块使用同一个闭环：

```text
旧代码/旧库只读证据
  -> 行为与数据契约
  -> 失败测试或差分用例
  -> 新项目最小根因修复
  -> Layui 与 CrmUI 同步适配
  -> 模块回归与浏览器验证
  -> 映射矩阵和差异报告关闭
```

运行时请求统一遵循：

```text
路由/中间件
  -> 参数、认证、权限和数据范围校验
  -> Controller 编排
  -> Service 状态机、事务和幂等控制
  -> Model/数据库
  -> 外部适配器或 Outbox
  -> JSON、重定向或 Blade 响应
  -> Layui/CrmUI JavaScript 消费
```

UI 不复制金额计算、权限判断、状态迁移等业务规则。两套页面族消费相同后端字段和错误语义，各自负责展示与交互。

## 8. 旧新逻辑对照方法

为每个旧入口建立唯一矩阵行，至少记录：

- 旧路由、HTTP 方法、权限和输入字段。
- 旧 Controller、调用链、表、队列、任务和外部依赖。
- 成功、失败、空数据、越权、重复提交和并发行为。
- 新项目对应入口、实现文件和自动化测试。
- 结果分类：等价、合理修正、缺失、阻断。
- 合理修正的旧行为、新行为、理由和测试证据。

只读旧库用于数据画像和查询证据。需要执行旧项目写流程时，必须把旧项目指向隔离副本 `hank_zl_data_baseline_test`，禁止回退到旧正式库。

差分测试对相同输入比较规范化结果，包括响应语义、状态、金额、权限结果和数据库变化。自动忽略明确的非业务差异，例如自动生成 ID、时间戳、request ID 和框架响应格式差异。

## 9. 异常与状态闭环

异常统一分为参数错误、认证/权限错误、业务状态冲突、并发冲突、外部服务失败和系统异常。

- 任何失败都返回明确状态，不吞异常，不返回空成功，不用默认数据掩盖错误。
- 数据库事务只覆盖本地原子写入，不把不可控网络调用放进长事务。
- 外部调用只有明确成功才能落本地成功状态；未知结果进入待核对或补偿队列。
- 资金、账户和返佣写路径必须使用幂等键、唯一约束、锁或可证明等价的并发控制。
- 审计记录包含 request ID、操作者、目标、原状态、新状态和失败原因，不记录密码或密钥。
- Blade 页面必须区分无权限、无数据、加载失败和业务禁用，不能用同一个空白状态代替。

## 10. 数据库隔离设计

固定数据库身份：

| 数据库 | 用途 | 写入规则 |
| --- | --- | --- |
| `hank_zl_data` | 旧正式数据证据 | 永久只读 |
| `hank_zl_data_baseline_test` | 旧项目行为验证副本 | 可重建隔离库 |
| `co_crmv5_schema_verify` | migration 空库重放 | 可重建隔离库 |
| `co_crmv5_migration_verify` | 数据迁移演练 | 可重建隔离库 |
| `co_crmv5_test` | 新项目全量测试 | 可重建隔离库 |
| `co_crmv5` | 新正式目标库 | 未再次授权前禁止写入 |

所有可清空命令必须在执行前验证真实主机、端口和数据库名，并要求目标严格匹配 allowlist。源库与目标库名称必须不同。任何身份不一致都在写入前失败。

隔离流程：

1. 在 `co_crmv5_schema_verify` 从空库重放全部 migration 并生成 schema 指纹。
2. 从只读旧库生成数据画像和显式映射。
3. 在 `co_crmv5_migration_verify` 执行迁移演练并校验表、行数、孤儿、状态和金额。
4. 从已验证结果构建 `co_crmv5_test`，运行新项目全部测试。
5. 修复问题后从第一步重新演练，不在失败库上手工打补丁。
6. 全部通过后仅生成正式迁移候选和报告，等待用户再次授权。

## 11. 视觉 C 设计系统

### 11.1 视觉语言

- 页面背景：近黑灰；内容表面：中性深灰；分隔线：可见但克制。
- 主文本使用高对比浅灰，次要文本使用中灰。
- 警示黄只用于主操作、当前焦点、选中态和高风险提醒。
- 成功使用绿色，失败使用红色，信息提示使用蓝色，避免所有状态都依赖黄色。
- 禁止装饰性渐变、光球和无业务意义的大面积卡片。
- 卡片圆角不超过 8px，不嵌套卡片；页面分区优先使用完整带状区域和清晰边界。
- 表格保持高密度但提供稳定行高、列宽、冻结操作区和明确 hover/focus 状态。

基础色值以背景 `#171717`、表面 `#242424`、边框 `#3A3A3A`、主文本 `#F5F5F5`、次文本 `#A3A3A3`、重点黄 `#F2C94C`、成功 `#34A853`、失败 `#EF5350`、信息 `#4DA3FF` 作为实施起点。只有在真实页面对比度或既有组件兼容测试失败时才调整，并在差异清单记录最终值和原因。

### 11.2 双页面族边界

- Layui 与 CrmUI 使用独立页面级 CSS/JS 入口，禁止跨族依赖视觉选择器。
- 无视觉依赖的请求、认证、国际化和格式化逻辑可以共享。
- 保留现有 DOM、表单字段、路由、权限和 JavaScript 挂载契约，除非测试证明它本身是缺陷。
- 现有 Lucide 资源用于熟悉的图标按钮；不熟悉的图标提供 tooltip 和可访问标签。

### 11.3 页面状态

每个页面至少覆盖正常、加载、空数据、失败、禁用、无权限和操作成功状态。表单错误靠近字段显示并保留用户输入；危险操作需要明确确认和处理中状态。

### 11.4 响应式验收

浏览器至少验证 `1440x900`、`1280x720`、`768x1024` 和 `390x844`。要求文字不截断、控件不移位、内容不遮挡、无无意义横向滚动，键盘焦点和触控尺寸可用。
