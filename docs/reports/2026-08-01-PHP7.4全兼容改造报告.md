# 2026-08-01 PHP 7.4 全兼容改造报告

> 生成时间：2026-08-01
> 核心要求：项目所有代码必须以 PHP 7.4 的写法兼容（即使环境为 PHP 8.0）

## 一、问题清单与根因

用户环境存在多版本 PHP（phpStudy：7.3.4 / 7.4.3 / 8.0.2 / 8.1.x），PhpStorm 终端 `php` 指向 7.3.4。
原依赖树按 PHP 8.0 解析安装，多个包使用 8.0 语法，导致 7.x 下 `php artisan` 直接 Parse error：

| 报错点 | 根因 |
|---|---|
| `vendor/ramsey/uuid/src/functions.php:55` | 参数尾随逗号 `): string`（PHP 8.0 语法），ramsey/uuid 4.9.0 要求 PHP ^8.0 |
| `vendor/symfony/translation/Translator.php:109` | `mixed` 类型（PHP 8.0），symfony/translation 6.0 要求 PHP ^8.0 |
| `vendor/symfony/string/UnicodeString.php:44` | `static` 返回类型（PHP 8.0） |
| `vendor/laravel/sail/.../InteractsWithDockerComposeServices.php:44` | 8.0 语法，sail 1.25 要求 PHP ^8.0 |
| `vendor/firebase/php-jwt` | 7.x 要求 PHP ^8.0 |
| `vendor/nette/utils` | 4.x 要求 PHP 8.0-8.5 |
| `vendor/psr/cache` | 2.0.0 tag 被 PHP-FIG 重打为 PHP >=8.0（官方已知事件） |
| 项目自身 `tests/Feature/SharedAjaxLifecycleClosureModuleTest.php:2994` | `catch (\Throwable)` 无变量捕获（PHP 8.0） |

## 三、用户环境指引（PhpStorm）

1. **PhpStorm 终端 php 为 7.3.4 的原因**：终端继承 PATH 中 php7.3.4nts 优先（或 CLI Interpreter 配置为 7.3.4）。
2. **7.3.4 不支持本项目**（typed properties 为 7.4+ 特性）。
3. **推荐配置**：Settings → Languages & Frameworks → PHP → CLI Interpreter → 选择
   `D:\Ruanjian\phpStudy_64\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe`
   （或 php7.4.3nts，项目现已双版本兼容）。
4. 也可在终端直接用绝对路径：`D:\Ruanjian\phpStudy_64\phpstudy_pro\Extensions\php\php8.0.2nts\php.exe artisan ...`
