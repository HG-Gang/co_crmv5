### 1.1 前台用户注册登录模块

#### 1.1.1 RegisterController::registerinto() —— 用户注册流程

**旧项目路由和方法：**
- `POST user/registerinto` → `RegisterController@registerinto`

**输入参数和含义：**

| 参数名 | 类型 | 必填 | 含义 |
|--------|------|------|------|
| `email` | string | 是 | 注册邮箱（同时作为用户名/登录号） |
| `password` | string | 是 | 登录密码（6-20位明文，服务端 Bcrypt 存储） |
| `inviter_id` | int | 否 | 邀请人用户 ID（用于建立代理上下级关系链） |
| `email_code` | string | 是 | 邮箱验证码（6位数字，5分钟有效） |
| `name` | string | 是 | 真实姓名 / 用户昵称 |
| `phone` | string | 否 | 手机号码 |

**执行的 SQL 逻辑和核心业务规则：**

```
第1步：图形验证码校验（captcha）
  → 读取 Session 中的 captcha 值与用户提交的 captcha 参数比对
  → 不匹配则返回错误，要求刷新图形验证码

第2步：邮箱验证码校验
  → 读取缓存中 key = "email_code:{email}" 的值
  → 与用户提交的 email_code 比对
  → 过期或错误返回"验证码错误"

第3步：邀请人（inviter_id）校验
  → SELECT * FROM user WHERE id = {inviter_id} AND is_agent = 1
  → 检查邀请人是否存在、是否为代理身份
  → 如果 inviter_id 不存在或不是代理，返回错误"邀请人不符"

第4步：邮箱唯一性查重
  → SELECT COUNT(*) FROM user WHERE email = {email} AND is_deleted = 0
  → 如果 count > 0，返回错误"邮箱已注册"

第5步：注册频率限制检查
  → 查询同一 IP 最近 120 秒内的注册记录
  → 如果存在，返回"注册频率限制"

第6步：生成用户编号
  → 读取自增序列 id_sequences，生成唯一 MT4 账号编号

第7步：创建用户记录（事务操作）
  → BEGIN TRANSACTION
  → INSERT INTO user (email, password_hash, name, phone, mt4_code, account_type, status, reg_ip) ...
  → INSERT INTO user_profile (user_id, real_name, balance, credit) ...
  → INSERT INTO user_auth (user_id, auth_type, auth_status) ...
  → 如果存在 inviter_id：
    → INSERT INTO agent_descendants (ancestor_id, descendant_id, depth)
    → 递归计算完整祖先路径
  → COMMIT

第8步：同步 MT4 账户
  → 调用 MT4 Manager API 创建真实交易账户
  → 更新本地 mt4_login 字段

第9步：发送注册成功邮件（异步队列）

第10步：写入登录日志（user_login_logs INSERT）
```

**返回值和含义：** 成功返回 code=0，data 含 user_id、email、mt4_code、mt4_login

**涉及数据库表：** `user`、`user_profile`、`user_auth`、`agent_descendants`、`id_sequences`、`user_login_logs`

#### 1.1.2 LoginController::signIn() —— 用户登录流程

**旧项目路由和方法：**
- `POST user/signIn` → `LoginController@signIn`

**输入参数和含义：**

| 参数名 | 类型 | 必填 | 含义 |
|--------|------|------|------|
| `email` | string | 是 | 邮箱或用户编号 |
| `password` | string | 是 | 登录密码 |
| `captcha` | string | 否 | 图形验证码（失败次数过多时必填） |

**执行的 SQL 逻辑和核心业务规则：**

```
第1步：图形验证码校验（可选）
  → 登录失败次数超阈值则强制校验 captcha

第2步：账号匹配查询
  → SELECT * FROM user WHERE (email={email} OR mt4_code={email}) AND is_deleted=0
  → 无匹配 → "账号不存在"

第3步：密码验证
  → MD5/Bcrypt 比对 password_hash
  → 失败 → "密码错误" → 记录失败日志

第4步：账号状态校验
  → status=0 → "已禁用" / status=2 → "已注销"

第5步：MT4 账户验证（可选）
  → 检查 mt4_users 中账户状态

第6步：写入 Session
  → $_SESSION 写入 user_id, email, account_type, mt4_code, login_time, login_ip

第7步：登录后操作
  → UPDATE user SET last_login_time, last_login_ip
  → INSERT user_login_logs + user_onlines
```

**返回值和含义：**
| `code`=0 | `data` 含 user_id, email, name, account_type, mt4_code, balance, redirect |

**涉及数据库表：** `user`、`user_profile`、`mt4_users`、`user_login_logs`、`user_onlines`

#### 1.1.3 UserForgetPswController —— 密码重置流程

**旧项目路由：** `POST user/forgetpsw` / `POST user/resetPassword`

**三步流程：**

| 步骤 | 输入 | SQL 逻辑 |

**涉及数据库表：** `user`、`password_change_logs`

### 1.5 前台交易佣金模块

#### 1.5.1 RealCommissionController —— 实时返佣

**旧项目路由：**
- `POST user/realtime/realtimeRebateSearch` → realtimeRebateSearch

**执行流程：**
```
查询 mt4_trades(CMD=6 且 COMMENT 含返佣关键词):
  SELECT t.*, u.email, u.name
  FROM mt4_trades t JOIN user u ON t.LOGIN=u.mt4_code
  WHERE t.CMD=6 AND t.CLOSE_TIME NOT NULL AND t.COMMENT LIKE '%rebate%'

从 COMMENT 字段提取返佣手数:
  COMMENT 格式: "From #18452 rebate_0.35_lot"
  正则提取: /rebate_([\d.]+)_lot/
  返佣金额 = 返佣手数 × 返佣比例 × 品种点值

代理树返佣分配:
  agent_descendants 逐级向上 → agent_levels.rebate_rate 分配
```

**涉及数据库表：** `mt4_trades`、`user`、`agent_descendants`、`agent_levels`、`commission_records`

#### 1.5.2 PositionSummaryController —— 仓位总结

**旧项目路由：**
- `POST user/position/positionSummarySearch` → positionSummarySearch

**复杂聚合逻辑（两步法）：**
```
第A步：构建临时表（agent_descendants 家族树所有用户ID列表）
第B步：聚合持仓数据（两轮聚合）
  第1轮：mt4_trades(CMD=0/1, CLOSE_TIME IS NULL) GROUP BY user_id
    → total_volume, buy_volume, sell_volume, total_profit, net_profit
  第2轮：同一批用户按品种分类聚合
    → 贵金属/外汇/指数/加密货币/能源/其他 → 六类 volume
  第3轮：已平仓订单盈亏统计（CLOSE_TIME NOT NULL）
```

##### 2.1.1.1 POST /api/front/auth/login（用户登录）

|------|------|
| **路由名称** | `front_api_auth_login` |
| **中间件** | 无（公开接口） |
| **控制器** | `AuthController@login` |

**完整执行链路：**

```
HTTP Request → Router 匹配 front_api_auth_login → AuthController@login

第1步：参数校验
  email: required|string, password: required|string|min:6|max:20

第2步：账号查询
  UserLogin::where('email', $email)->where('is_deleted', 0)->first()
  null → code=1006 "账号不存在"

  失败 → code=1007 "密码错误"

  status=0 → code=1008 "已禁用"，status=2 → code=1009 "已注销"

  Cache::put("sso:user:{$user->id}", $jti, 7200)

第7步：写入登录日志
  UserLoginLog::create([user_id, login_ip, login_time, user_agent])

第8步：返回 JSON
  {code:0, data:{access_token, token_type, expires_in, user:{id, email, name, mt4_code}}}
```

**涉及数据库表：** `user_logins`、`user_infos`、`user_login_logs`  
**Service 调用：** `JwtService::issue()`


## 第四部分：安全防护中间件链路详解

### 4.1 四层防护架构总览

```
HTTP 请求
  │
  ├─ [api 中间件组] SetLocale + throttle:api(60次/分钟) + SubstituteBindings
  │
  ├─ [第1层: JWT 鉴权] JwtAuthMiddleware
  │   解析 Bearer token → 验证签名/有效期 → 设置 Auth guard
  │   失败 → TOKEN_MISSING(1010) | AUTH_FAILED(1011)
  │
  ├─ [第2层: SSO 单点登录] SingleSignOn
  │   Cache::get("sso:{guard}:{sub}") 比对 jti
  │   不一致 → SSO_CONFLICT(1039) 被踢下线
  │
  ├─ [第3层: 接口权限] CheckPermission (仅后台)
  │   白名单检查 → 超级管理员检查 → permissions.api_route 校验
  │   失败 → PERMISSION_DENIED
  │
  ├─ [第4层: 数据范围] AdminDataScopeService (注入 Controller)
  │   role_data_scopes + admin_agent_bindings
  │   过滤查询结果集
  │
  ▼
Controller 业务逻辑
```

### 4.2 第1层：JwtAuthMiddleware（JWT 令牌鉴权）

**文件位置：** `app/Http/Middleware/JwtAuthMiddleware.php`

**执行流程：**

```
handle($request, $next, $guard = 'user')

第1步：Token 提取
  → Authorization Header → Bearer {token}
  → 或 ?token={token} 查询参数（兼容旧版）
  → 无 token → code=1010 "TOKEN_MISSING"

第2步：Token 验证
  → JwtService::verify($token)
  → 解析载荷: {sub, guard, jti, iat, exp}
  → 签名校验（HMAC-SHA256）
  → 过期检查（exp > time()）
  → 失败 → code=1011 "AUTH_FAILED"

第3步：Guard 验证
  → $payload['guard'] === $guard
  → 不匹配 → code=1011

第4步：用户验证
  → UserLogin::find($payload['sub'])
  → 不存在或 is_deleted → code=1011

第5步：Auth 登录
  → Auth::guard($guard)->login($user)
  → 写入请求属性:
    → request()->attributes->set('jwt_payload', $payload)
    → request()->attributes->set('jwt_guard', $guard)
    → request()->attributes->set('jwt_token', $token)
```

**JWT Token 结构：**
```
Header:  {"alg": "HS256", "typ": "JWT"}
Payload: {
  "sub": 123,            // 用户ID
  "guard": "user",       // 守卫类型: user | admin
  "jti": "uuid-string",  // JWT ID, 用于SSO校验
  "iat": 1700000000,     // 签发时间
  "exp": 1700007200      // 过期时间 (默认7200秒=2小时)
}
Signature: HMAC-SHA256(base64(header) + "." + base64(payload), APP_KEY)
```

### 4.3 第2层：SingleSignOn（SSO 单点登录）

**文件位置：** `app/Http/Middleware/SingleSignOn.php`

**执行流程：**

```
handle($request, $next, $guard)

第1步：获取 JWT 载荷
  → $payload = request()->attributes->get('jwt_payload')
  → $sub = $payload['sub']
  → $jti = $payload['jti']

第2步：缓存查询
  → $key = "sso:{$guard}:{$sub}"
  → $cachedJti = Cache::get($key)
  → 如果没有缓存（首次登录或已过期）:
    → Cache::put($key, $jti, config('jwt.ttl'))
    → 通过

第3步：JTI 比对
  → $cachedJti !== $jti
  → 不一致 → code=1039 "SSO_CONFLICT" (被踢下线)
  → 一致 → 通过

第4步：缓存续期
  → Cache::touch($key, config('jwt.ttl'))
```

**SSO 踢人机制：**
```
用户A在设备1登录: Cache::put("sso:user:123", "jti-aaa")
用户A在设备2登录: Cache::put("sso:user:123", "jti-bbb")
设备1下次请求: Cache::get("sso:user:123") = "jti-bbb" != "jti-aaa"
  → SSO_CONFLICT → 设备1被踢下线
```

**后台强制下线实现：**
```
OnlineUserController@forceOffline($userId)
  → Cache::forget("sso:user:{$userId}")
  → 用户下次请求 SSO 中间件时找不到缓存
  → 重新写入当前 token 的 jti → 通过
  → 但如果在此之前用户已经有其他登录 → 会被新登录踢掉
```

### 4.4 第3层：CheckPermission（接口权限鉴权）

**文件位置：** `app/Http/Middleware/CheckPermission.php`

**仅用于后台模块**（`check.permission:admin`），前台用户不检查 permissions 表。

**执行流程：**

```
handle($request, $next, $guard)

第1步：获取路由名称
  → $routeName = Route::currentRouteName()
  → null → 通过（未命名路由不校验权限）

第2步：白名单检查
  → isPermissionWhiteRoute($routeName)
  → 白名单路由列表:
    - admin_api_menus (当前菜单)
    - admin_api_profileInfo (个人资料)
    - admin_api_updateProfile (更新资料)
    - admin_api_logout (登出)
    - admin_api_refreshToken (刷新token)
    - admin_api_changePassword (修改密码)
    - admin_api_uploadAvatar (上传头像)
  → 匹配 → 通过

第3步：超级管理员检查
  → isSuperAdmin()
  → Auth::id() === 1 (admin_logins 第一条记录)
  → 或 Auth::user()->role->name === 'super_admin'
  → 通过（超级管理员拥有所有权限）

第4步：权限匹配
  → Permission::where('api_route', $routeName)
      ->where('guard_type', $guard)
      ->where('status', 1)
      ->first()
  → 如果权限记录不存在或未启用 → PERMISSION_DENIED

第5步：角色关联校验
  → $adminRoleId = Auth::user()->role_id
  → RolePermission::where('role_id', $adminRoleId)
      ->where('permission_id', $permission->id)
      ->exists()
  → 不存在 → PERMISSION_DENIED
```

**权限注册数据流：**
```
permissions 表注册:
  {
    name: "用户列表",
    slug: "admin.user.list",
    api_route: "admin_api_userList",
    guard_type: "admin",
    status: 1
  }

管理员角色分配:
  roles: { id: 2, name: "运营专员" }
  role_permissions: { role_id: 2, permission_id: 45 }

请求 /api/admin/userList:
  CheckPermission → 路由名 = admin_api_userList
  → 查 permissions WHERE api_route='admin_api_userList' AND guard_type='admin' AND status=1
  → 查 role_permissions WHERE role_id=2 AND permission_id=45
  → 通过/拒绝
```

### 4.5 第4层：AdminDataScopeService（数据范围过滤）

**文件位置：** `app/Services/AdminDataScopeService.php`

**执行流程：**

```
applyScope($query, $table)

第1步：超级管理员检查
  → Auth::id() === 1 → 不过滤，返回原始 query
  → Auth::user()->role->name === 'super_admin' → 不过滤

第2步：角色数据范围
  → $scopes = RoleDataScope::where('role_id', Auth::user()->role_id)->get()
  → 类型:
    → 'all' → 不过滤
    → 'self' → WHERE {$table}.id = Auth::id()
    → 'custom' → WHERE {$table}.id IN (自定义范围内的用户ID列表)
    → 'agents' → WHERE {$table}.id IN (
        SELECT descendant_id FROM agent_descendants
        WHERE ancestor_id IN (绑定代理ID列表)
      )

第3步：管理员代理绑定
  → $agentIds = AdminAgentBinding::where('admin_id', Auth::id())
      ->pluck('agent_id')->toArray()
  → 如果 agentIds 不为空:
    → WHERE {$table}.id IN (
        SELECT descendant_id FROM agent_descendants
        WHERE ancestor_id IN ({agentIds})
      )
  → 结合第2步的范围取交集

第4步：注入 WHERE 条件
  → $query->where(function($q) use ($conditions) {
      // 组合多个 WHERE 条件
    })
```

| 检查点 | 实现机制 | 失败响应 | 覆盖范围 |
