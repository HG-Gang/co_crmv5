# 2026-07-25 旧前台直属客户详情页协议闭环报告

> 本文记录旧路由 `GET /user/cust/show_direct_cust_info/{role}/{uid}` 的 Blade、控制器、数据字段和权限边界迁移闭环。它仅代表该路由已完成可重复验证，不代表旧项目全部模块已迁移完成；全量进度以 `docs/audits/旧项目模块逻辑迁移核验矩阵.md` 为准。

## 1. 本轮目标与问题

旧项目中，代理在直属客户页面打开详情弹层时，会渲染 `user.user_detail.show_direct_cust_info`。该页面不是简单的客户摘要，而是固定了资料字段、联系方式脱敏、状态文案和管理员角色登录历史入口。

新项目原来的 `AgentController::legacyUserDetailPage()` 虽然已有代理树授权，但返回的是另一张“入金、出金、返佣、订单、收益”统计卡片。它缺少旧详情页的客户资料字段，导致旧页面调用同名路由时出现协议偏差。

本轮解决的问题：

1. 旧客户资料字段没有按原顺序和原含义返回。
2. 手机、邮箱没有在服务器端按旧规则脱敏，存在原始联系方式进入页面的风险。
3. `role=admin` 的登录历史表格入口缺失，且角色值必须严格等于旧 Blade 的 `admin`。
4. 旧页面的“已认证”要求账户、身份证、银行卡三项同时通过，不能只凭新表的单一 `auth_status` 误判。
5. 必须保留代理树可见范围，未登录、普通客户、跨树访问不能读取页面内容。

## 3. 项目 2：新项目实现链路

新项目目录：`D:\Software\PhpProject\Demo\co_crmv5`

### 3.1 路由与访问边界

路由位于 `routes/web.php`：

```text
GET user/cust/show_direct_cust_info/{role}/{uid}
-> Front\AgentController@legacyUserDetailPage
-> 路由名 legacy_user_customer_detail
-> web 中间件
```

`AgentController::legacyUserDetailPage()` 的执行顺序：

1. `legacyRouteUserId($first, $second)` 解析目标业务用户 ID。对于当前路由，`first` 是 `role`，`second` 是 `uid`。
2. ID 不存在或不为正数时返回 HTTP 404，表示路由参数不能定位有效客户。
3. `legacyFrontUserLogin()` 读取当前会话登录人。会话不存在或 `account_type != 1` 时返回 HTTP 403，表示只有代理可以查看下级详情。
4. `canViewUser()` 通过 `FrontLegacyData::userScopeIds()` 校验目标客户是否处于当前代理树。跨树目标返回 HTTP 403，页面正文不会泄露客户姓名、联系方式或余额。
5. 从 `user_infos` 预加载 `login`、`level`、`groupConfig`、`parent`、`auth` 关系；目标不存在时返回 HTTP 404。
6. 路由名严格匹配 `legacy_user_customer_detail` 时，调用 `legacyDirectCustomerDetailFields()` 组装旧 Blade 字段，并渲染 `front.legacy.direct_customer_detail`。
7. 同一控制器保留 `show/user_detail/{userId}/{role}` 的既有统计卡片分支，避免将两张不同旧页面的字段混合。

### 3.3 Blade 与登录历史链路

新视图文件：`resources/views/front/legacy/direct_customer_detail.blade.php`。

1. Blade 只接收已经由控制器脱敏并映射完成的 `fields`，通过只读 `<input>` 渲染，避免模板自行接触原始敏感数据。
2. 当且仅当 `showLoginHistory=true` 时显示 `id="login_history"` 表格。
3. 控制器只在路由参数严格等于字符串 `admin` 时传递 `showLoginHistory=true`。`Admin`、`ADMIN`、`agent` 等值不显示该入口，和旧 `$role == 'admin'` 一致。
4. 表格 JavaScript 使用相对地址 `/user/cust/loginHistorySearch/{uid}`、CSRF Token、`page` 与 `rows=20` 请求数据。
5. 响应中的 `rows` 被安全写入 `textContent`，不使用 HTML 拼接客户可控字段；`total` 用于上一页、下一页状态。
6. 请求成功且 `rows=[]` 表示当前页没有登录记录；HTTP 非成功或网络失败显示“登录历史加载失败”。

### 3.4 返回结果中文说明

| 返回结果 | 中文含义 |
| --- | --- |
| HTTP 200 且包含资料字段 | 当前登录代理有权查看目标客户，返回已脱敏的客户资料。 |
| HTTP 200 且含 `#login_history` | 代理使用精确 `role=admin` 打开详情，前端可继续请求登录历史。 |
| HTTP 200 且不含 `#login_history` | 正常代理详情页，资料可见但不开放管理员登录历史入口。 |
| HTTP 403 | 未登录、普通客户账号或目标不在当前代理树，禁止读取详情。 |
| HTTP 404 | `uid` 无效或业务用户不存在。 |
| 登录历史 `rows=[]`、`total=0` | 最近四周没有有效登录记录，或当前会话无权读取目标历史；兼容接口不区分两种情况，避免越权探测。 |
| 登录历史 HTTP 419 | 缺少或无效 CSRF Token，`web` 中间件拒绝伪造请求。 |

### 5.1 RED：修复前失败

新增 `FrontLegacyDirectCustomerInfoDataContractClosureModuleTest` 后，原实现返回统计卡片而不是旧详情字段，首个用例失败：

```text
Failed asserting that response contains "账户ID".
```


这两次失败分别证明“旧字段契约缺失”和“认证条件被错误简化”。
