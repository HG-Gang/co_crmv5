# 旧前台本人交易汇总闭环报告

- 旧项目：`D:\Php-project\Php\new_co_gmtk_crmV3`
- 新项目：`D:\Software\PhpProject\Demo\co_crmv5`

- 查询入口：`POST /user/position/positionSummary2Search`
- 旧控制器：`App\Http\Controllers\User\PositionSummary2Controller`

- 新查询控制器：`App\Http\Controllers\Front\PositionController@positionSummary2Search`

本模块是“当前登录用户本人”的 MT4 交易汇总，不是代理树持仓汇总。旧页面只允许按 `startdate`、`enddate` 查询自己的资金余额变动、已平仓盈亏、手续费、库存费和六类品种手数。

## 2. 旧项目逻辑核验

旧页面使用 `startdate`、`enddate` 提交 `POST /user/position/positionSummary2Search`。表格固定展示以下字段：

| 字段 | 中文含义 | 旧页面结果含义 |
| --- | --- | --- |
| `total_yuerj` | 入金 | 指定时间内命中旧 MT4 入金代码且金额大于零的余额变动总额 |
| `total_yuecj` | 出金 | 指定时间内命中旧 MT4 出金代码且金额小于零的余额变动总额，保留负数 |
| `total_net_worth` | 净入金 | 入金减去出金绝对值 |
| `total_profit` | 已平仓盈亏 | 有效已平仓交易的 `profit` 总额 |
| `total_comm` | 手续费 | 有效已平仓交易 `commission` 绝对值总额 |
| `total_swaps` | 库存费 | 有效已平仓交易中负库存费之和 |
| `total_noble_metal` 至 `total_stock` | 六类品种手数 | 根据品种分组归类后的成交量，原始 MT4 `volume` 除以 100 |
| `total_volume` | 总手数 | 所有有效已平仓交易的成交量总和，原始值除以 100 |

旧项目的余额备注统计不是自然语言检索，而是固定 MT4 代码白名单。新项目已逐项对齐：

- 入金：`DBAA`、`DBCT`、`DBGN`、`DBMN`、`DBPA`、`DBPN`、`DBSN`、`DBTN`、`DBUN`、`DBZN`、`DBAD`、`WBIR`。
- 出金：`WBAA`、`WBCN`、`WBCT`、`WBHN`、`WBIN`、`WBPN`、`WBSN`、`WBTN`、`WBAD`、`DBZR`。
- `DBCN` 属于返佣入账，不能计入本人入金；`deposit-manual` 等普通说明文字也不能计入，避免扩大旧统计口径。

## 3. 路由与执行链路

```text
GET /user/position/summary2
  -> LegacyFrontAuthenticate
  -> LegacyPageController::positionSummary2
  -> front_layui::position.summary2
  -> module-page.js 读取 data-api、日期字段与列定义
  -> POST /user/position/positionSummary2Search
  -> PositionController::positionSummary2Search
  -> legacyFrontUserId 解析旧 session 或前台身份
  -> selfLoginIdSumData
  -> user_trades + symbol_prices
  -> formatPositionSummary2Data
  -> JSON code=1000、data.list、data.totalRow
  -> module-page.js 渲染本人汇总表格
```

各步骤的作用和结果：

1. `LegacyFrontAuthenticate` 先校验旧前台登录态。未登录时不渲染敏感页面，返回登录跳转或旧接口统一鉴权错误。
2. `positionSummary2()` 只渲染 `summary2.blade.php`。该视图不包含代理 ID、代理姓名、品种下拉框或下级钻取动作，解决此前错误复用代理树汇总页的问题。
3. Blade 通过 `data-api="/user/position/positionSummary2Search"`、`data-method="POST"` 和 `startdate/enddate` 声明前端请求契约。共享脚本会在初始加载、搜索和重置后使用同一契约请求数据。
4. `positionSummary2Search()` 从当前身份取得用户 ID。不存在对应 `user_infos` 用户时返回 `code=1000`、`count=0`、空列表，中文含义是“查询成功但当前账号没有可汇总资料”，不是服务器错误。
5. `selfLoginIdSumData()` 仅查询 `user_trades.user_id=当前用户`。日期优先使用 `startdate/enddate`，兼容 `date_from/date_to`；未传时以 `2024-01-01` 至当天为默认范围。
6. 余额类交易要求 `cmd=6` 且金额符号、固定备注代码同时正确。这样可以区分真实入出金、返佣、普通说明性余额变动。
7. 交易类汇总只处理 `cmd=0..5`、`close_time>1970-01-01 00:00:00`、`margin_rate!=0` 的有效已平仓单，排除未平仓和无效记录。
8. `symbol_prices` 的启用品种分组 `1..6` 决定贵金属、外汇、原油、指数、货币、股票六类手数；无法归类的交易仍计入总手数，不会伪造任意分类值。
9. `formatPositionSummary2Data()` 将金额、手数统一转为两位小数。手续费以正数展示，出金和负库存费保留负数，页面会使用负数样式提示资金流出或成本。
10. JSON 的 `data.list.data` 是表格行，`data.totalRow` 是同一统计口径的汇总对象，`data.chain` 仅保留当前用户链路用于统一响应结构，不开放代理树钻取。

## 4. 本次修复与中文注释

此前 `GET /user/position/summary2` 错误绑定 `LegacyPageController@positionSummary`，会渲染 `/api/front/positions/summary` 并开放代理树筛选，导致页面职责、接口和数据范围均与旧项目不符。

本次改动：

- 在 `LegacyPageController` 新增带中文职责、边界和返回值说明的 `positionSummary2()`。
- 新增 `summary2.blade.php`，以中文 Blade 注释记录页面用途、输入、接口、返回数据与不复用代理树页面的原因。
- 旧入口和现代 `/front/position/summary2` 入口均渲染同一专用 Blade，避免不同导航入口出现统计口径分叉。
- 路由和测试文件补充中文注释，说明为什么必须绑定专用页面以及 `frame=1` 的 iframe 渲染边界。

本模块未新增数据库迁移：已有 `user_trades`、`user_infos`、`symbol_prices`、`commission_records` 表结构足以承载旧逻辑。
